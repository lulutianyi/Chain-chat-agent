# 链谈 Agent

面向中小微采购商家的供应商智能接待、分层谈判和筛选系统。

> 核心原则：大模型负责理解和表达，程序负责底线、评分和决策。

## Demo 包含什么

- **采购工作台**：编辑目标价、起订量、账期、资质门槛和转人工阈值，查看供应商分层。
- **AI 实时谈判**：查看对话、底线校验、加权评分和谈判摘要；高质量候选会停止 AI 自动回复并提醒人工接管。
- **供应商入口**：接收报价、起订量、资质、地区、备货周期和配合方案，自动匹配商品需求并返回分类结果。
- **测评实验室**：基于 `json_output/` 测试集回放规则引擎（1500 条报价用例），并对 200 条供应商话术抽样检验 AI 回复的策略命中与越权风险。

## 决策流程

```text
供应商提交条件
        │
        ▼
程序硬性底线校验 ─── 不通过 ──▶ 礼貌结束洽谈
        │通过
        ▼
程序加权评分
        ├── 未达阈值 ──▶ AI 继续议价
        └── 达到阈值 ──▶ 停止 AI 回复 ──▶ 人工接管
```

AI 拉锯过程中，供应商给出新的报价/起订量/交期/账期时，程序会重新执行底线校验并更新评分与分类：评分达到阈值即转人工，触碰硬性底线则立即礼貌结束洽谈。条款抽取由 AI 完成，评分与分类始终由程序计算，AI 不参与决策。

## 本地启动

### 1. 后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\uvicorn app.main:app --reload --port 8000
```

后端文档：`http://localhost:8000/docs`

### 2. 前端

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local
npm run dev
```

网页：`http://localhost:3000`

## 大模型配置

在 `backend/.env` 中设置：

```dotenv
DEEPSEEK_API_KEY=your-key-here
DEEPSEEK_MODEL=deepseek-chat
```

未配置密钥时，后端会使用可重复演示的本地谈判回复；规则与评分逻辑不受影响。密钥不应写入源码或提交到 Git。

## 数据库

本地 Demo 默认使用 SQLite，首次启动会生成商品、采购规则、供应商、谈判和消息表。切换 PostgreSQL / Supabase 时，只需修改 `backend/.env`：

```dotenv
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/postgres
```

## 使用流程

前后端启动后访问 `http://localhost:3000`（默认跳转到采购工作台），左侧导航包含四个页面。推荐按下面的动线完整走一遍「被动接待 → 分层筛选 → 转人工」闭环。

### 第 1 步：商家录入采购底线（采购工作台 `/dashboard`）

1. 点击右上角「商品库管理」，新增或编辑商品。
2. 填入整套采购底线：目标采购价、硬性价格上限、最高起订量、最长交期、最长账期、转人工分数、必备资质（逗号分隔）和优先地区。
3. 点击「添加并启用」后，商品会立即出现在供应商入口；停用只隐藏商品，不删除历史记录。

### 第 2 步：供应商上门报价（供应商入口 `/supplier`）

1. 依次完成四步：选择供货商品 → 填写企业信息（名称、联系人、电话、地区、备货周期）→ 填写报价、起订量、账期与配合方案 → 勾选资质（营业执照、质检报告、可开发票）并上传至少一份资质文件（图片或 PDF，供商家人工核验）。
2. 点击「校验并提交方案」，系统立即执行硬性底线校验和加权评分，自动创建供应商档案与谈判会话，并当场返回分类结果。

### 第 3 步：按分层结果分流

| 结果 | 发生什么 |
| --- | --- |
| 淘汰 | 提示条件不匹配（附触线原因），后续消息由系统礼貌收尾，不再打扰商家 |
| AI 拉锯 | 可点击「扮演该供应商开始洽谈」进入谈判页，AI 自动议价、索取可核验信息 |
| 转人工 | AI 自动回复停止，谈判页顶部出现接管提醒，等待商家处理 |

### 第 4 步：商家处理洽谈（实时谈判 `/negotiate`）

1. 左侧是多会话列表（含实时评分），右侧是供应商评分卡、底线校验明细、「AI 谈判摘要」（最新条款、谈判轮次、评分轨迹，无需读完对话）与资质文件人工核验区。
2. 顶栏铃铛实时提示待接管的优质候选会话，点击直接进入对应谈判。
3. 顶部可切换「采购方视角」和「模拟供应商」两种身份发言，方便一人演示完整对话。
4. 达到转人工条件的会话，点击「现在接管」或「停止 AI 并接管」后即可人工回复。
5. 普通会话人工沟通后，可点「恢复 AI 自动谈判」交还 AI；优质候选按规则不允许恢复自动回复。
6. 供应商在对话中给出新条款时，系统自动重新评分并调整分类（会话中出现「程序重新校验评分」的系统提示），商家端通过实时状态流同步看到最新分数。

### 第 5 步：查看经营统计（采购工作台 `/dashboard`）

「今日接待 / AI 自动谈判中 / 优质候选 / 为您节省」四张指标卡由真实接待与谈判记录自动生成，点击卡片可在下方查看对应的供应商明细。

### 第 6 步（可选）：验证引擎质量（测评实验室 `/evaluation`）

- **规则引擎测评**：一键回放全部 1500 条报价用例（不调用大模型），输出总体准确率、混淆矩阵、分组准确率与误判明细。
- **AI 话术抽样测评**：选择话术类型和抽样数量（1–20 条），真实调用大模型生成回复，并用「策略命中 + 越权红线」双闸打分；未配置 API Key 时以本地固定回复兜底，并在结果中标记 fallback 数量。
- 测评只读测试集文件，不写入正式的供应商与谈判数据表。

## 评分模型

| 维度 | 权重 |
| --- | ---: |
| 价格竞争力 | 35 |
| 起订量 | 20 |
| 资质完整度 | 25 |
| 地区匹配 | 10 |
| 沟通配合度 | 10 |

硬性规则优先于评分：超过价格上限、起订量上限、交期上限或缺少必备资质时，即使其他项得分较高也会直接淘汰。

## 项目结构

```text
frontend/   Next.js + TypeScript + Tailwind + shadcn/ui 四页工作台
backend/    FastAPI + Pydantic + SQLAlchemy + SSE + DeepSeek 接入
```

本版本用于本地闭环演示。未来公开发布时，建议将互动应用部署在支持 Next.js 与 FastAPI 的服务上；Hexo 可用于官网、产品介绍和帮助文档，不建议承载实时谈判主应用。
